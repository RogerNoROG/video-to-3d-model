#   环境：Ubuntu 24.04.5 (WSL2) / Python 3.12.3 / x86_64
#   导出：2026-09-18
#
# 与 requirements.txt 的区别：
#   requirements.txt 只有 5 条宽松范围约束，且**不足以重建可用环境**，原因是
#   `scipy` 和 `nvidia-cudnn-cu12` 都不在任何已声明依赖的传递链上（open3d 与
#   fastapi 都不依赖它们），只装 requirements.txt 一定装不到 → 见下方说明。
#   本文件把实测通过的组合逐条锁死（==），用于换环境时精确复现。
#
# 用法：
#   python3.12 -m venv .venv
#   ./.venv/bin/python -m pip install -r requirements.lock.txt
#   # 国内网络建议加速：
#   ./.venv/bin/python -m pip install -r requirements.lock.txt \
#       -i https://pypi.tuna.tsinghua.edu.cn/simple
#
# 两个容易被漏掉、但缺了就跑不起来的依赖（已显式列在「直接依赖」区）：
#   1) scipy —— 代码里 scipy.spatial.cKDTree 用于顶点上色、点间距测量、点云连通
#      分量清理（tools/ 下多个脚本）。open3d 不依赖 scipy，只装 requirements.txt
#      会以 ModuleNotFoundError 崩在运行期，而不是安装期。
#   2) nvidia-cudnn-cu12 —— COLMAP 的学习型特征（ALIKED）走 GPU 由 ONNX Runtime
#      驱动，需要 cuDNN 9。缺了它 colmap 会**直接 abort（不是回退 CPU）**；再叠加
#      start.sh 里的 MODEL_API_ALLOW_CPU_FALLBACK=false，等于完全无法建模。
#      装好后无需另设环境变量：app/main.py 的 cudnn_library_dir() 会自动探测
#      site-packages/nvidia/cudnn/lib 并注入子进程的 LD_LIBRARY_PATH。
#
# 注意：pip 与 setuptools 的版本已注释在文件末尾 —— 它们不影响运行期行为，
#       锁死只会让 pip 自我降级，因此默认不参与安装。
# ===========================================================================
